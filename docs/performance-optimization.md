# 性能与轻量化实测（2026-10-23）

本轮已缩小桌面代码、减少 Main → preload 的流式传输，并在隐藏/最小化时释放玻璃引擎引用。胶囊待机的界面进程和 JS 堆占用下降；**展开、动态背景及反复切换后的整个进程树内存没有证实下降，部分场景更高**。后者主要差异位于 GPU 进程，不能把代码体积或传输量下降当作整体 RAM 优化成功。

修改保留现有未提交的拖动动画实验。未修改用户的 DSH 安装、Profile、会话或插件运行时缓存，未发布新版本。

## 已实施

1. `@glass/protocol/initial-projection` 提供仅含初始状态工厂的入口。renderer 不再为了初始化空状态执行 Zod 和整套协议 schema；Main 的输入验证原样保留，既有协议入口继续导出同一函数。
2. Main、preload、renderer 启用生产压缩，保留构建器的许可证注释策略，不改 React 版本和 Electron 安全选项。
3. 会话内增量：已有会话只发送变化字段；转录和活动按位置发送变化行，保留顺序、重复 ID、删除及空列表语义。未变化 Todo 不再反复传送。完整快照、revision 检查、缺帧恢复、每 300 次完整刷新和审批校验保留，格式见 [本地投影 IPC](02_PROTOCOL.md)。
4. Main 通过 `WindowState.visible` 发布原生可见状态。隐藏/最小化时停止材质尺寸观察、移除 SVG 滤镜并清空引擎贴图缓存；恢复时按原参数重建。使用原生状态是因为本机透明窗口隐藏后 `document.hidden` 仍为 false。

没有降低取样分辨率、刷新节奏、转录长度或历史保留上限；透明/磨砂背景仍保留原有三个 RGB 位移通道。

## 代码体积

单位为十进制 kB，包含构建输出；不是 npm 包或完整 Electron 运行时的尺寸。

| 构建内容 | 优化前 | 优化后 |
| --- | ---: | ---: |
| renderer JS | 876.98 kB | 294.67 kB |
| Main JS | 424.47 kB | 214.37 kB |
| preload JS | 6.45 kB | 4.26 kB |
| 全部桌面构建输出（JS/CSS/HTML） | 1,419.53 kB | 606.79 kB |

构建输出减少约 **57.3%**，renderer JS 减少约 **66.4%**。本机 Electron 44.8.0 的完整 `dist` 仍为 386,247,394 字节；此次未裁剪运行时、语言资源或许可证，因此不能宣传完整安装包缩小了 57%。

## 流式更新基准

使用真实 `ProjectionPublisher/Receiver`，合成 100 个彼此独立的会话；选中会话有 1,000 个 Todo、100 条活动、60 条转录，进行 360 次流式更新。交替执行优化前后版本各三轮，时间取中位数；序列化采用 Node V8，往返采用 `structuredClone`，最后严格核对完整状态。

| 场景 | 序列化字节：前 → 后 | 减少 | 往返时间中位数：前 → 后 |
| --- | ---: | ---: | ---: |
| 只观察增量帧 | 63,299,201 → 205,601 | 99.7% | 436.8 → 175.2 ms |
| 保留生产每 300 次完整刷新（含 1 次快照） | 80,847,140 → 17,928,800 | 77.8% | 524.5 → 265.4 ms |

这是合成的 Main/preload 编解码基准，不是用户 DSH 任务耗时或画面 FPS。`contextBridge` 当前仍将完整投影复制给页面；本轮没有消除这一段复制，也不能把 preload 内的对象复用当作页面中的对象身份保证。

## 内存实测及限制

同一 Windows x64、150% DPI、生产 Electron；每种构建各两轮，每个场景四次采样，先取每轮中位数，再取两轮中位数。未调用手动 GC 或工作集裁剪。进程树包含受控背景测试窗口和原生取样助手，**不包含 DSH Host**；使用 OS private working set，不能直接与任务管理器分组数字比较。

| 场景 | 进程树私有工作集 MiB：前 → 后 | 界面 JS 堆 MiB：前 → 后 |
| --- | ---: | ---: |
| 胶囊、未取样 | 221.6 → 204.9 | 5.80 → 4.72 |
| 胶囊、原生取样 | 215.4 → 205.3 | 5.41 → 4.92 |
| 展开、静态背景 | 368.1 → 419.0 | 4.23 → 3.53 |
| 展开、变化背景 | 400.0 → 469.8 | 4.23 → 3.53 |
| 18 次形态切换后 | 437.1 → 551.6 | 4.49 → 3.81 |
| 再次收起 | 314.8 → 467.0 | 4.90 → 3.86 |
| 隐藏 | 285.6 → 396.9 | 4.98 → 3.95 |

原生取样胶囊的界面进程本身约 **45.3 → 36.1 MiB**。JS 层收益与删除 renderer 的 schema 实例一致，但不能据此解释 GPU 进程的变化。隐藏后滤镜节点确实归零，Chromium/驱动的分配池仍可能保留内存；本轮两次优化后隐藏场景的进程树中位数分别约 532 和 262 MiB，波动很大。没有长期压力曲线或控制变量实验，**不能排除回归，也不能声称 GPU 内存优化成功**。

## 下一步轻量化方法

| 方法 | 依据与预期收益 | 实施前需要的验证 |
| --- | --- | --- |
| 将投影接收器放到 renderer，使局部帧穿过 contextBridge | 当前仍有完整 Projection 的页面复制；可减少 100 会话高频更新下的分配，并让 memo 真正复用未变对象 | 新的窄 IPC API；断帧 fail-closed、初始同步竞态、旧夹具、跨会话审批和真实 100 会话内存/延迟对照 |
| 单独定位 GPU 分配池和形态切换资源 | 本轮整树差异主要来自 GPU，JS 堆已经下降；这是进一步降低常驻 RAM 的主要调查对象 | 分别关闭“新增隐藏回收”和“生产压缩”进行控制变量复测，固定原生运动/材质/背景并记录长时间回落曲线；保持全部 RGB 通道和截图一致 |
| 对光学 IPC 做显式缓冲所有权交接 | 变化背景下仍有原生管道、Main 序列化、页面画布上传；有进一步减少临时分配的空间 | 先测真实拷贝次数；转移/复用不得破坏同步发送后立即清零的隐私约定，必须验证 ACK、退出、reload 与迟到帧 |

不直接裁掉 Electron 组件、语言包、审批内容或历史保留，也不将主动降画质作为本轮轻量化方案。替换桌面引擎属于独立架构工程，需要先证明现有原生材质、安全隔离与审批行为等价。
