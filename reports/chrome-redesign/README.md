# 截图反馈：边缘、窗口操作、详情入口

2026-10-17，用户前三张圈图为问题证据，第四张为视觉方向。目标是连续光学边缘、向内留白的轻量控件和清晰的渐进展开，保留真实限定区域折射与实色功能文字。

## 设计参考

- [Apple · Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)：参考透明控件、内容与控制层的区分及嵌套圆角关系，避免把玻璃当成固定色块。
- [Fluent 2 · Shapes](https://fluent2.microsoft.design/shapes/)：参考圆角、描边和形状之间的一致性，而非混用不同风格按钮。
- 用户第四张图：借鉴整块玻璃、内缩控件、纤细进度和琥珀待确认入口。未把这张效果图当作实机材质验证。

## 实现与根因

- 左上装饰短横删除。右上角独立蓝色方按钮改为一个内缩的透明圆角操作组，使用统一SVG收起/菜单图标；移除额外标题条高度，保留真实按钮、可访问名称、键盘焦点与右键菜单。
- 标题/会话选择器明确预留右侧空间，设置/活动返回按钮移到标题左侧。操作组避开窗口圆角及原生调整尺寸区域。
- 详情和调试折叠行移除默认实心三角，使用自定义SVG、完整点击行、悬停与旋转反馈；仍使用原生details/summary保留键盘展开。1.5px边缘采用分段高光，保留透镜产生的实际色散，不添加整面蓝底或彩虹壁纸。
- 方形底角已在当前150% DPI的原生Acrylic路径复现。CSS圆角、Electron setShape，以及额外实验的Win32 SetWindowRgn均未清除系统Acrylic方形填色；DWM圆角偏好仅改变系统小圆角，仍不匹配26 DIP表面。测试只对本测试窗生效。根据实际失败结果停用该对照选项，旧acrylic偏好规范化为transparent，其余偏好保持。实际预览旧偏好已在同目录备份为glass-ui.before-chrome-redesign-20261017.json。原生裁剪实验未加入运行时。

`scripts/chrome-corner-probe.mjs` / `probe-native-rounding.ps1` 为隔离诊断。截屏保存在临时目录，背景为本测试拥有的纯色窗口。固定像素(0,0)/(5,5)从预期背景RGB(146,178,200)被系统层改为(90,122,144)，说明原来的灰角不是页面边框。

## 验证范围

`scripts/chrome-design-acceptance.mjs` 验证旧偏好回退、控件边距、标题避让、设置返回与详情Enter展开/收起，并生成受控样张。`scripts/ui-clarity-acceptance.mjs` 检查亮/暗三形态、当前背景覆盖、标题/工具组不重叠、功能色及审批禁用语义。另回归窄高度审批和实际拖动。系统角像素另作原生截图对照，不能以页面透明截图替代。

单测35项（新增旧材质迁移），lint/typecheck/build通过。实际视觉偏好仍待用户评价；DSH真实审批保持BLOCKED。

原生四角实测：旧acrylic输入迁移、transparent、solid三种情况下，四个(距边3px)角点均为测试背景RGB(146,178,200)，不再残留原生灰角，见`native-corners.json`。亮暗三形态标题/会话控件均不覆盖操作组，审批250/320/340 DIP固定操作栏与详情滚动通过。

最终桌面smoke通过四形态、会话切换、并发请求、重连、完成/断线、实际指针缩放和隐藏恢复，22次原生形变采样，renderer错误0。实际按住拖动四条轨迹均保持viewport固定，持续收到12个不同位置的真实背景输入。上述结果不替代全DPI/多屏或用户审美验收。
